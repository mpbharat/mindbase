Session 1 Build Strategy

The spec is done. 47 tasks await. What do we build first?

A

Foundation First

Setup → DB schema → deploy empty shell to Vercel. End of session: a live URL at stellaros.life with nothing on it, but all infrastructure solid. 3D comes next session.

Pros

  • Infra never blocks visual work
  • Clean deploy pipeline early
  • DB schema is the hardest decision — resolve it first

Cons

  • Nothing to see for the whole session
  • Less motivating
B

3D Scene First (Recommended)

Setup → static 3D galaxy with hardcoded data → get the visual language right. DB and CRUD in the next session. End of session: a beautiful, breathing galaxy on screen.

Pros

  • Immediate visual feedback — you see SOL alive
  • Validates the 3D approach before committing to DB schema
  • Game feel established early — everything else follows from it

Cons

  • Static data needs to be wired later
  • Two passes on nodes (visual then DB)
C

Full Stack Slice

Setup → DB schema → one domain node end-to-end (Business node: visible in 3D, data from DB, clickable, right sidebar shows it). A thin vertical slice of everything.

Pros

  • Proves the full architecture works together
  • Real data in the 3D from day 1

Cons

  • More complex to orchestrate
  • Slower to get something satisfying on screen
  • Might expose DB schema decisions mid-session
